# AI Quota Watch

The website half of QuotaPilot. Lives in `site/` of the QuotaPilot repo; `quotapilot share` sends data to it.

Static site that tracks usage limits, plan changes, API prices and community-measured output speed
for ChatGPT, Claude, Grok and Gemini. Live at https://aiquotawatch.pages.dev/ (Cloudflare Pages; GitHub Pages copy as backup). English first, Traditional Chinese via the language toggle
(or `?lang=zh`). Every number carries its source URL and the date it was checked.

## Run locally

```sh
python3 -m http.server 8765
# open http://127.0.0.1:8765/
```

The page loads `data/*.json` with `fetch`, so it must be served over HTTP (not opened as a file).

## Standalone preview

`python3 scripts/build-preview.py /tmp/ai-quota-watch-preview.html` bundles the current site, styles, scripts and datasets into one HTML document. Add `--demo` for labelled example community data. Dataset loading works without network access; external source links and the opt-in report form still require a connection.

## Update data

1. Edit `data/plans.json` (plan quotas), `data/models.json` (calculator models), `data/changes.json` (timeline).
2. Every entry needs `source` (https URL), a `checked` date, and `confidence`: `official` only when read on the vendor's own page, otherwise `reported`.
3. Bump `lastReviewed` in each file.
4. Run the checks:

```sh
node scripts/validate-data.mjs   # every number has a source + date, en + zh text
node scripts/check-i18n.mjs      # en and zh strings match
npm test                         # all of the above plus aggregator tests
```

## Publish data

Daily data commits go live with `scripts/publish-site-data.sh` (run from the repo root; `--dry-run` shows the diff only). It pushes a commit onto `origin/main` that changes only `site/data/`, so other local commits are never pushed. The site deploy is triggered by a push to main that touches `site/**`. Validation runs first and blocks the publish if it cannot run (no Node.js, or uncommitted changes in `site/data/`); `--skip-validate` overrides that. After a publish, `origin/main` holds a data commit that is not in your local history, so run `git fetch origin && git merge origin/main` before the next normal push of main.

## Community data

Visitors report speed, ratings, quota used and limit/reset events with the form in the Community section.

- The form previews the exact payload and sends it only to the anonymous collector (`community.collector` in `assets/config.js`); there is no named or GitHub route.
- `../.github/workflows/community-data.yml` pulls the collector export, runs `scripts/aggregate.mjs`, and stores only `community.json` on the `community-data` branch. `../.github/workflows/site-pages.yml` publishes the site to GitHub Pages.
- `?demo=1` loads `data/community.sample.json` (generated by `npm run sample`, labelled as example data on the page).
- Tests: `npm test`.

## Model ranking (`/models/`)

`scripts/models-pages.mjs` (called by `build-pages.mjs`) builds, in English and Traditional Chinese, `/models/` (ranking table, filters, "what fits me" calculator and electricity calculator),
`/models/local-llm-speed-by-mac-chip` and `/models/llm-api-price-comparison` from `data/models.json` and `data/community.json`. The generated pages are git-ignored like the other generated pages, and the
deploy workflow copies `site/models/`. The logic and the row renderers live in `assets/models-core.js`, which runs both in Node (static HTML) and in the browser (`assets/models-page.js`: filters, sortable
columns, calculators; it fetches only `data/models.json` and `data/community.json` from this site and sends nothing). The table works without JavaScript; the filters and calculators are hidden until the script runs.

- Cloud rows: every model in `models.json` with input, output and cache-read prices, a blended price (3 input : 1 output at list price), context, community speed (a published row from 3 people, otherwise a rounded
  preliminary figure) and community rating. Local rows come only from `community.json` `localRuns` (opt-in reports, see PRIVACY.md); none are shown, and the Mac-chip page says so honestly, while there is no data.
- Calculators run in the page: monthly input and output tokens (or paste `quotapilot stats --json`, parsed in the browser), currency (default from the browser's region), optional USD exchange rate, electricity price per kWh,
  watts (a typical value per chip when empty) and hours per day. The values are kept in this browser's local storage only.
- **Smartness is an empty, hidden column.** No third-party benchmark number is stored, fetched or shown (`validate-data.mjs` forbids such fields, and a test checks the column stays hidden). Turn it on only together with a licensed source.

## Sponsor, install box, ads (`assets/config.js`)

- `sponsor.url`: GitHub Sponsors (or any `https://`) link used by the nav chip, the hero link, the support card, the footer and the community invite, and by the generated pages (read at build time). Empty, or anything that is not `https://`, hides every sponsor element. `sponsor.label` overrides the "Sponsor" text; empty = translated default. `.github/FUNDING.yml` drives the GitHub "Sponsor" button on the repo.
- `install.commands` / `install.notesUrl` / `install.sourceUrl`: the Homebrew box in the hero and the community invite. index.html carries the same commands as a no-JS fallback (a test keeps them in sync). Copy includes installation and the launch/status command, joined with ` && ` (`;` in Windows PowerShell).
- `ads.enabled`: there are no placeholder boxes any more. One hidden slot (`#adTop`) appears only when this is `true`; add the network's hosts to the CSP in `_headers` and the meta tag in `index.html` first.
- `affiliates.<provider>`: put an affiliate URL here to replace the official pricing link in "Get a plan". The disclosure line appears automatically and links get `rel="sponsored"`.

## Theme

Light/dark follows the system. The nav button (auto → light → dark) and the footer select store the choice in `localStorage["aqw-theme"]`; `assets/theme.js` applies it in `<head>` before the stylesheet so there is no flash of the wrong theme. Colours are CSS variables in `assets/style.css`; the dark values appear twice there (system preference and forced dark) and must be kept in sync.

## Deploy

`site-pages.yml` deploys `site/` to GitHub Pages after Pages is enabled with source "GitHub Actions". The primary deployment is Cloudflare Pages; GitHub Pages is the project-prefix backup. Data and assets resolve relative to the application script so both paths work.

## Data notes (2026-11-02)

- OpenAI's pricing and help pages block automated reading, so ChatGPT plan rows and GPT-6.1 Sol API price are marked Reported.
- Third-party benchmark scores are not republished: the calculator links to Artificial Analysis instead. Their website terms allow personal, non-commercial use only.
- Vendors publish relative multiples, not message counts, so bars compare plans within one vendor only.
